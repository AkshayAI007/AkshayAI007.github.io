decisions:
  title: Structure first, so quality can be measured.
  items:
  - title: Type every agent’s output with Pydantic.
    insteadOf: Free-form text, parsed afterwards.
    because: Sixty fields need types the validator can check and downstream systems can trust.
    tradeoff: A schema change ripples through every agent that produces it.
  - title: Run the three generator agents in parallel.
    insteadOf: A sequential chain, one agent after another.
    because: The agents are independent, so wall-clock time is bound by the slowest one, not the sum.
    tradeoff: Conflicts between agents surface at the validator and must be resolved there.
  - title: Repair failed fields in a self-correcting loop.
    insteadOf: Failing the whole profile, or regenerating it end to end.
    because: Only the broken fields are redone, which saves tokens and time.
    tradeoff: The loop needs a cap so a stubborn field can’t run up cost.
  - title: Score profiles with a 10-parameter LLM-as-Judge rubric in MLflow.
    insteadOf: Spot-checking outputs by hand.
    because: A prompt or model change shows up as a score change before it shows up in production.
    tradeoff: The judge needs its own calibration against human review.

<Story kicker="THE CONTEXT" title="A profile is more than a form.">
Onboarding a business means describing who it is, how it looks and how it sounds. Assembled by hand it is slow; generated in one prompt it is inconsistent and hard to check.
</Story>
<Story kicker="THE CONSTRAINT" title="Sixty fields, and each one has to hold up.">
Every field needed a type, a validation rule and a way to be fixed without regenerating the whole profile — plus a score that engineers and stakeholders could both read.
</Story>
