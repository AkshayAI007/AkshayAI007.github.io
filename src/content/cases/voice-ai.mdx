decisions:
  title: Verification comes before the conversation does.
  items:
  - title: Split the call across three specialised agents.
    insteadOf: One voice agent carrying verification, support and recovery in a single prompt.
    because: Each agent gets a narrow job and only the tools it needs, so verification can’t drift into support, and each one is tested on its own.
    tradeoff: Handoffs to engineer, each one a latency and state-transfer risk.
  - title: Verify with a one-time code, after recording consent.
    insteadOf: Security questions, or verifying lazily once the caller asks for something sensitive.
    because: A code sent to the number on file proves the caller holds that phone, and no account data reaches the model until it matches. Disclosure and consent open every call, as all-party-consent states require.
    tradeoff: A few seconds of friction up front, and a dependency on SMS delivery.
  - title: Stream STT → LLM → TTS over WebRTC, with SRTP on the SIP leg.
    insteadOf: A press-1 phone menu, or recording the request and processing it later.
    because: Turn-taking and interruptions only feel natural when every hop is streamed, and resolving the request on the first call is what removes the queue.
    tradeoff: A strict latency budget that constrains every model and tool choice.
  - title: Save the conversation state every turn, so a dropped call resumes.
    insteadOf: Asking the caller to ring back and start again from verification.
    because: The Callback agent picks up at the exact step with full context, so the caller never notices the break.
    tradeoff: A write on every turn, and tool calls made idempotent so a resumed call never files a ticket twice.
  - title: File tickets through structured tool calls.
    insteadOf: A free-text call summary for a human to re-key.
    because: The ticket is actionable the moment the call ends, and every field is validated before it reaches Salesforce or the other integrations.
    tradeoff: Schemas to keep in sync with each integration, and an escalation path when intent is ambiguous.

<Story kicker="THE CONTEXT" title="Two days, for a phone call.">
Inbound service requests entered a manual queue. Customers waited up to two days before work began, while identity checks, information capture and ticket creation crossed several systems and teams.
</Story>
<Story kicker="THE CONSTRAINT" title="Real-time doesn’t forgive mistakes.">
The system had to hold a natural conversation with no audible lag, prove who the caller was before touching their account, follow US call-recording consent rules on every call, and survive a dropped line without making the caller start again.
</Story>
